# Genie Code workspace instructions

Guidance for this Genesis Workbench (GWB) workshop workspace. These apply across notebooks; keep them
scoped to GWB / model work so unrelated tasks are unaffected.

## Any life-sciences / bio-ML workflow → use the GWB skills

For **any** life-sciences, bio-ML, drug-discovery, genomics, or single-cell workflow in a notebook here,
lean on the installed GWB skills rather than improvising. Start with **`@genesis-workbench`** (the entry
point / router), which points to the specific skill:

- run a model on an input (fold, dock, generate molecules, ADMET, embed sequences/cells) → **`@gwb-serving-endpoints`**
- design or optimize a protein for a target → **`@protein-design-from-paper`**
- similarity search / cell annotation / any index query → **`@gwb-vector-search`** (proteins: **`@gwb-sequence-search`**; cells: **`@gwb-single-cell`**)
- a long or heavy workflow run as a job → **`@gwb-batch-jobs`**
- scale a forward pass across GPUs or build an index → **`@gwb-ray-batch-inference`** (+ **`@gwb-serverless-gpu`**)
- see what's deployed and awake → **`@gwb-discover-resources`**

## Working with Genesis Workbench models

- **Call GWB through its serving endpoints (and MCP tools) — do not `import genesis_workbench`.** Use
  `WorkspaceClient.serving_endpoints.query(...)`. Treat GWB as a service, not a library.
- **Discover endpoint names at runtime** by listing serving endpoints and matching the model slug (e.g.
  `esmfold`, `boltz`, `proteina_complexa`, `netsolp`), rather than hard-coding `gwb_<prefix>_<model>_endpoint`.
  Fail loud if a required model isn't found — GWB reaps idle endpoints, so warm them before running.
- **Payload styles:** `inputs=[...]` (ESMFold, Boltz), `dataframe_records=[{...}]` (ProteinMPNN,
  developability), `dataframe_split=DataframeSplitInput(...)` (Proteina-Complexa, DiffDock).

## Protein design & optimization tasks

- For "use this paper to design/optimize a protein/binder" requests, apply the **`@protein-design-from-paper`**
  skill. It covers binder-vs-protein, binder-vs-ligand, motif scaffolding, de novo monomer, and optimization,
  and generates the funnel (generate → ESMFold fold gate → Boltz complex ipTM → developability → composite
  reward) into the current notebook.
- Reproduce the paper's AF2-multimer interface filter with **Boltz-2** co-folding (`protein_A:…;protein_B:…`),
  ranked on `iptm` — GWB's AlphaFold2 is monomer-only.

## Honest scope

- In-silico design does **enrichment and prioritization**, not measurement. ipTM is a docking *confidence*,
  not an affinity; developability outputs (NetSolP, DeepSTABp, PLTNUM, MHCflurry) are proxies that decide
  which designs to order — PLTNUM is a 0–1 ranker, not hours. State this in generated notebooks.
